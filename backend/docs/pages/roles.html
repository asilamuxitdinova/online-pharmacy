Roles

There are three roles. Each includes everything the roles above it in this table can do.

RoleWhoMay
(none)AnyoneBrowse the catalog and categories, read these docs, check health.
customerPeople buying medicineManage their own profile, addresses, cards, prescriptions, orders and refunds.
staffPharmacistsRead every order and customer (including taxpayer numbers), review prescriptions, approve or reject refunds, run sales reports, act on a customer's behalf.
adminAdministratorsList all users, change roles, disable, enable and delete accounts.

Rules

  • The role is checked on every request from the database. A role change takes effect on the very next call; there is no need to sign in again.
  • Someone else's record answers 404, not 403, so the API never confirms that it exists.
  • A 403 role_required names the role that was needed in required_role.
  • A disabled account gets 403 account_disabled on every call.
  • Administrators cannot change, disable or delete their own account.

Acting on a customer's behalf

Staff and admins may send X-Act-As: <customer id> to see exactly what that customer sees and to change their orders. Staff-only endpoints refuse a request that carries X-Act-As. Responses made this way carry an X-Acting-As header.

Without X-Act-As, staff can read any order but cannot change it (403 act_as_required).
