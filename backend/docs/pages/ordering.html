Ordering

An order holds 1 to 20 different products, at most 10 of each. Prices are fixed when the order is created.

Life of an order

StatusMeaningWhat can happen next
pending_paymentCreated, not paid.Change (PUT, PATCH), pay, cancel or delete.
paidPaid in full.Refund. A paid order cannot be cancelled, changed or deleted.
partially_refundedSome money returned.Further refunds up to the amount left.
refundedAll money returned.Nothing.
cancelledCancelled before payment.Delete.

Changing an order

PUT /orders/{id} replaces the whole order, items included: send every field. PATCH /orders/{id} changes only delivery details (delivery method, address, prescription, note) and leaves the items alone.

Safe retries

POST /orders, POST /orders/{id}/pay and POST /orders/{id}/refunds accept an Idempotency-Key header. Repeating a request with the same key and body returns the first answer (with Idempotent-Replayed: true) instead of acting twice. The same key with a different body is refused with 422 idempotency_key_reused.

Stock

Stock is checked when an order is created and taken when it is paid. If a product sells out in between, payment answers 409 insufficient_stock. The slow POST /stock-checks job checks every branch.

Invoices

GET /orders/{id}/invoice returns a printable HTML page, not JSON.
